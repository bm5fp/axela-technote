# Image

## Dockerfile

Dockerfileは、イメージをビルドする手順をテキスト形式で記述したファイルです。1行1命令（インストラクション）で構成され、`docker build`コマンドによってこの手順が順に実行され、最終的なイメージが生成されます。

|主な命令|役割|
|---|---|
|FROM|ベースとなるイメージを指定（すべてのDockerfileの起点）|
|RUN|イメージビルド時にコマンドを実行（パッケージのインストールなど）|
|COPY / ADD|ホスト側のファイルをイメージにコピー（ADDは圧縮ファイルの自動展開やURL取得にも対応）|
|WORKDIR|以降の命令のためのカレントディレクトリを指定|
|ENV|環境変数を設定|
|EXPOSE|コンテナが利用するポートを文書化（実際のポート公開は`docker run -p`で行う）|
|ENTRYPOINT / CMD|コンテナ起動時に実行するコマンドを指定|

## レイヤ構造とキャッシュ

Dockerイメージは、Dockerfileの命令1つ1つに対応する「レイヤ」が積み重なった構造になっています。各レイヤは差分（前のレイヤからの変更点）のみを保持し、複数のイメージ間で共通のレイヤはディスク上で共有されます。

|特性|概要|
|---|---|
|レイヤの独立性|一度作られたレイヤは不変（イミュータブル）|
|ビルドキャッシュ|同じ内容の命令かつ入力に変更がなければ、そのレイヤは再ビルドされずキャッシュが再利用される|
|キャッシュの無効化|該当レイヤより前の命令、またはCOPY元ファイルの内容が変わると、それ以降のレイヤは再ビルドされる|

このキャッシュの仕組みを踏まえ、「変更頻度の低い命令（依存関係のインストールなど）を先に、変更頻度の高い命令（アプリケーションコードのコピーなど）を後に書く」ことで、ビルド時間を大幅に短縮できます。

## ビルドプロセス（docker build, BuildKit）

`docker build`は、Dockerfileと指定されたビルドコンテキスト（COPY/ADDの対象となるディレクトリ）を元に、レイヤを1つずつ積み上げてイメージを生成するコマンドです。

|項目|概要|
|---|---|
|ビルドコンテキスト|`docker build .`の`.`のように指定するディレクトリ。この配下のファイルだけがCOPY/ADDで参照できる|
|.dockerignore|ビルドコンテキストから除外するファイル/ディレクトリを指定（不要なファイル送信の削減、キャッシュ効率化）|
|BuildKit|現在の標準ビルドエンジン。並列ビルド、キャッシュのマウント、マルチステージビルドの効率化などを実現|
|マルチステージビルド|複数のFROMを1つのDockerfile内で使い、ビルド専用のステージと実行用の最終イメージを分離することで、最終イメージのサイズを削減する手法|

## レジストリ（Docker Hub, プライベートレジストリ）

レジストリは、Dockerイメージを保存・配布するためのサーバです。`docker pull`/`docker push`を通じてイメージのやり取りを行います。

|項目|概要|
|---|---|
|Docker Hub|Docker社が提供する公開レジストリ。公式イメージや多数のOSSイメージが公開されている|
|プライベートレジストリ|組織内でイメージを管理するための非公開レジストリ（例：Amazon ECR, Google Artifact Registry, Harbor）|
|タグ|同一イメージ名に対するバージョン識別子（例：`nginx:1.25`）。`latest`は明示的にバージョンを指定しない場合のデフォルトタグであり、必ずしも最新版を保証するものではない|
|イメージダイジェスト|イメージ内容から算出されるハッシュ値。タグと異なり、内容が変わらない限り不変な参照として利用できる|

本番運用では、`latest`タグへの依存を避け、明示的なバージョンタグやダイジェストを指定することで、意図しないイメージの更新を防ぐことが推奨されます。
