# Storage

Kubernetes環境では、永続化はPersistentVolume/PersistentVolumeClaim/CSIが担うため、ここで扱うDocker単体のマウント機能は主に単体でのDocker利用時に関係する内容です。概要のみ押さえておきます。

## Volume

コンテナを削除すると書き込みレイヤのデータは失われるため、Volumeはコンテナのライフサイクルとは独立してデータを永続化する仕組みです。Dockerデーモンが管理し、複数コンテナからの共有マウントも可能です。

## Bind Mount

ホスト上の任意のディレクトリ・ファイルを、そのままコンテナ内にマウントする方式です。開発時にソースコードをリアルタイム反映したい場合などに使われます。

## tmpfs Mount

ホストのメモリ上にのみデータを保持するマウント方式です。コンテナ停止と同時に消えるため、機密データの一時保管に向いています。

## データの永続化パターン

「DBデータはVolume」「開発中のソースコードはBind Mount」「機密な一時データはtmpfs」のように、データの性質に応じてマウント方式を使い分けます。
