# Fundamentals

## Gitとは

Gitは、ソースコードの変更履歴を管理する分散型バージョン管理システムです。中央のサーバに依存する集中型（SVNなど）と異なり、全ての開発者が履歴の完全なコピー（リポジトリ全体）をローカルに持つ点が特徴です。これにより、ネットワーク接続なしでもコミットや履歴の閲覧が可能で、中央サーバが一時的にダウンしても作業を継続できます。

## スナップショットモデル

Gitの本質的な設計思想は、「差分の記録」ではなく「スナップショットの記録」です。

|項目|概要|
|---|---|
|差分ベース（他のVCSに多い方式）|各バージョンを、直前のバージョンとの差分（変更点）として保存する|
|スナップショットベース（Git）|コミットのたびに、その時点の全ファイルの状態をまるごと記録する。ただし変更のないファイルは実体を再保存せず、直前のバージョンへの参照だけを持つため、実際のディスク使用量は差分ベースと同程度に抑えられる|

この設計により、任意の2つのコミット間の比較や、特定時点への復元が高速かつシンプルに行えます。

## Gitオブジェクトモデル（blob, tree, commit）

Gitは、`.git`ディレクトリ内部で全てのデータを「オブジェクト」として管理しています。各オブジェクトは内容のSHA-1（またはSHA-256）ハッシュ値によって一意に識別されます。

|オブジェクト|概要|
|---|---|
|blob|ファイルの内容そのもの（ファイル名や属性は含まない、純粋なデータ）|
|tree|ディレクトリ構造を表すオブジェクト。ファイル名とパーミッション、対応するblob（またはサブディレクトリのtree）のハッシュ値を保持する|
|commit|1つのtree（その時点のスナップショット全体）へのポインタ、親コミットへのポインタ、作成者、コミットメッセージなどを持つオブジェクト|
|tag|特定のコミットに対して、恒久的な名前（バージョン番号など）を付けるオブジェクト|

コミットを1つ作るたびに、変更されたファイルのblobと、それらをまとめるtree、そして親コミットへのリンクを持つcommitオブジェクトが新たに作られ、これらが数珠つなぎになることでプロジェクト全体の履歴（有向非巡回グラフ、DAG）が構成されます。

## リポジトリの構造（.git ディレクトリ）

`git init`を実行すると作成される`.git`ディレクトリには、リポジトリの全ての情報が格納されています。

|ディレクトリ/ファイル|概要|
|---|---|
|objects/|blob, tree, commit, tagといった全オブジェクトの実体（ハッシュ値ごとに圧縮保存される）|
|refs/|ブランチやタグが指す先（実際にはコミットハッシュへのポインタ）|
|HEAD|現在チェックアウトしているブランチ（またはコミット）を指すポインタ|
|index|ステージングエリアの実体。次にコミットする内容が記録されている|
|config|そのリポジトリ固有の設定（リモートURL、ユーザ情報の上書きなど）|

`.git`ディレクトリさえあれば、そのプロジェクトの全履歴を復元できるため、これがリポジトリを「クローンする」ということの実体になります。

## ワーキングツリー・ステージングエリア・リポジトリ

Gitでの変更は、3つの領域を経て記録されます。

|領域|概要|
|---|---|
|ワーキングツリー|実際に編集しているファイルが存在する作業ディレクトリ|
|ステージングエリア（インデックス）|`git add`によって「次のコミットに含めたい変更」を一時的に登録しておく領域|
|リポジトリ（.git内）|`git commit`によって、ステージングエリアの内容が正式な履歴として記録される場所|

|コマンド|役割|
|---|---|
|git add|ワーキングツリーの変更を、ステージングエリアに登録する|
|git commit|ステージングエリアの内容を、新しいコミットとしてリポジトリに記録する|
|git status|各領域における変更状況（未追跡、変更あり未ステージ、ステージ済みなど）を確認する|

このステージングエリアという中間領域があることで、「編集した全ての変更」ではなく「意味のある単位に絞った変更」だけを1つのコミットにまとめる、といった柔軟なコミット作成が可能になっています。
