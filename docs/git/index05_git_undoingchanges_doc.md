# UndoingChanges

Gitには、変更を取り消すための複数のコマンドがありますが、「どの段階の変更を」「どの程度取り消すか」によって適切なコマンドが異なります。

## git restore（ワーキングツリー・ステージングの取り消し）

`git restore`は、まだコミットしていない変更を取り消すための、比較的新しい（Git 2.23以降の）コマンドです。

|コマンド|効果|
|---|---|
|git restore <file>|ワーキングツリーの変更を、直前のコミットの状態に戻す（編集内容を破棄する）|
|git restore --staged <file>|ステージングエリアから変更を取り除く（`git add`を取り消す。ワーキングツリーの変更内容は保持される）|

## git reset（コミット履歴・ステージングの巻き戻し）

`git reset`は、ブランチの指す先（HEAD）を過去のコミットに移動させるコマンドです。その際、ワーキングツリーやステージングエリアをどこまで巻き戻すかをモードで選べます。

|モード|HEAD（コミット履歴）|ステージングエリア|ワーキングツリー|
|---|---|---|---|
|--soft|移動する|変更しない（差分はステージ済みのまま残る）|変更しない|
|--mixed（デフォルト）|移動する|直前のコミットの状態に戻す（変更はワーキングツリーに残る）|変更しない|
|--hard|移動する|直前のコミットの状態に戻す|直前のコミットの状態に戻す（編集内容も完全に破棄される）|

`--hard`は未コミットの変更も含めて完全に破棄するため、実行前に本当に不要な変更かを確認する必要があります。また、既にリモートにpush済みのコミットに対して`reset`を行うと、ローカルとリモートの履歴が食い違うため注意が必要です。

## git revert（安全な取り消し）

`git revert`は、過去のコミットの内容を打ち消す、新しいコミットを作成する方法です。

|項目|概要|
|---|---|
|resetとの違い|`reset`が履歴そのものを書き換える（過去のコミットをなかったことにする）のに対し、`revert`は履歴を書き換えず、「打ち消しの変更」を新たなコミットとして追加する|
|共有ブランチでの安全性|既に他の開発者と共有済みの履歴に対しては、`reset`ではなく`revert`を使うのが基本。履歴を書き換えないため、他の開発者の作業に影響を与えない|

「ローカルでの、まだ誰とも共有していない履歴の整理には`reset`、共有済みの履歴を安全に取り消すには`revert`」という使い分けが基本方針になります。

## git reflog（安全網としての参照ログ）

`git reflog`は、HEADやブランチの指す先が、いつどのように変化してきたかの記録です。通常のコミット履歴（`git log`）とは異なり、ブランチから見えなくなったコミット（`reset --hard`で「消した」つもりのコミットなど）へのポインタも一定期間保持されます。

|項目|概要|
|---|---|
|用途|`reset --hard`やリベースなどで「うっかり失った」ように見えるコミットを復元するための安全網|
|復元方法|`git reflog`で該当のコミットハッシュを確認し、`git reset --hard <hash>`や`git checkout <hash>`でその状態に戻る|
|保持期間|デフォルトで一定期間（通常90日程度）経過すると、ガベージコレクションの対象になり消去される|

「Gitでの操作は、多くの場合reflogによって取り消せる」という安心感があるため、履歴の書き換えを伴う操作（reset、rebaseなど）も過度に恐れずに扱えます。
