# Remote

## リモートリポジトリとは

リモートリポジトリは、ネットワーク越しに存在する（GitHubやGitLabなどでホストされることが多い）別のGitリポジトリです。Gitは分散型であるため、開発者それぞれが持つローカルリポジトリと、共有の基点となるリモートリポジトリとの間で、履歴のやり取りを行います。

|コマンド|役割|
|---|---|
|git clone <url>|リモートリポジトリの内容全体（履歴を含む）をローカルに複製する|
|git remote -v|設定されているリモートリポジトリの一覧とURLを確認する|
|git remote add <name> <url>|新しいリモートリポジトリを登録する（デフォルトの名前は`origin`）|

## fetch / pull / push

リモートリポジトリとローカルリポジトリの間で履歴をやり取りする、基本となる3つの操作です。

|コマンド|概要|
|---|---|
|git fetch|リモートリポジトリの最新情報を取得するが、ローカルの作業中のブランチには反映しない（`origin/main`のようなリモート追跡ブランチだけが更新される）|
|git pull|`git fetch`に加えて、取得した内容を現在のブランチに自動的にマージ（またはリベース）する|
|git push|ローカルのコミットを、リモートリポジトリに送信して反映する|

`git pull`は内部的に`fetch`＋`merge`（デフォルト）を行っているため、「まず`fetch`で状況を確認してから、必要な統合方法（merge/rebase）を選んで実行する」という手順を踏むことで、意図しないマージコミットの発生を防げます。

## リモート追跡ブランチ

リモート追跡ブランチは、「最後に通信した時点での、リモートブランチの状態」をローカルに記録しておくための特殊なブランチです。

|項目|概要|
|---|---|
|命名規則|`<リモート名>/<ブランチ名>`（例：`origin/main`）という形式で表される|
|更新タイミング|`git fetch`または`git push`を実行したときにのみ更新される（自動的に最新の状態に追従するわけではない）|
|用途|ローカルの`main`ブランチと`origin/main`を比較することで、「自分のローカルはリモートに対して何コミット進んでいる/遅れているか」を把握できる|

## 上流ブランチ（upstream）の設定

ローカルブランチとリモートブランチを紐づけておくことで、`git pull`/`git push`を引数なしで実行できるようになります。

|コマンド|概要|
|---|---|
|git push -u origin <branch>|pushと同時に、そのリモートブランチを上流ブランチとして設定する|
|git branch --set-upstream-to=origin/<branch>|既存のローカルブランチに対して、後から上流ブランチを設定する|

上流ブランチが設定されていると、`git status`で「リモートに対して何コミット進んでいる/遅れているか」が自動的に表示されるようになります。

## Pull Request / Merge Request経由の連携

多くのチーム開発では、リモートリポジトリへの直接のpushではなく、GitHubやGitLabが提供するPull Request（Merge Request）の仕組みを介してブランチを統合します。

|項目|概要|
|---|---|
|フォーク|自分のアカウント配下に、元のリポジトリの複製を作成する（オープンソースプロジェクトへの貢献など、直接pushする権限がない場合によく使われる）|
|Pull Requestの作成|フィーチャーブランチの変更内容を、`main`などの対象ブランチに取り込みたいという「提案」として登録する|
|レビューとマージ|他の開発者がコードレビューを行い、承認された後にマージが実行される（この一連の流れは[Collaboration](index06_git_collaboration_doc.md)で扱う）|

このPull Requestの仕組み自体はGit本体の機能ではなく、GitHub/GitLabなどのホスティングサービスが独自に提供している、コラボレーションのためのレイヤです。
