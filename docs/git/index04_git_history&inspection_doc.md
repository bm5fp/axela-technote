# History&Inspection

## git log

`git log`は、コミット履歴を確認するための基本的なコマンドです。

|オプション|概要|
|---|---|
|--oneline|各コミットを1行で簡潔に表示する|
|--graph|ブランチの分岐・マージの構造を、ASCIIアートのグラフとして可視化する|
|--author=<name>|特定の作成者によるコミットだけに絞り込む|
|-p / --patch|各コミットで実際に変更された差分（diff）も合わせて表示する|
|<path>|特定のファイル・ディレクトリに関するコミットだけに絞り込む|

`git log --oneline --graph --all`のように組み合わせることで、全ブランチの分岐状況を俯瞰する形で確認できます。

## git diff

`git diff`は、異なる時点・場所の内容の差分を表示するコマンドです。比較対象の指定によって、様々な差分を確認できます。

|コマンド|比較対象|
|---|---|
|git diff|ワーキングツリー vs ステージングエリア（まだaddしていない変更）|
|git diff --staged|ステージングエリア vs 直前のコミット（addしたが、まだcommitしていない変更）|
|git diff <commit1> <commit2>|任意の2つのコミット間の差分|
|git diff <branch1>..<branch2>|2つのブランチの指す先のコミット間の差分|

「今どの段階の差分を見ているか」を意識することが、`git diff`を正しく使う上での基本になります。

## git blame

`git blame`は、ファイルの各行が「いつ」「誰によって」「どのコミットで」追加・変更されたかを表示するコマンドです。

|用途|概要|
|---|---|
|変更意図の調査|一見不可解なコードに対して、対応するコミットメッセージやPull Requestを遡り、変更の背景を理解する|
|バグの原因調査|問題のある行がいつ・どのコミットで追加されたかを特定し、そのコミットの内容を詳しく調べる|

ファイル単位ではなく行単位で履歴を追えるため、大きなファイルの中の特定のロジックがいつ・なぜ生まれたのかを調査する際に有効です。

## git bisect

`git bisect`は、「正常に動いていたコミット」と「問題が発生しているコミット」の間を、二分探索によって効率的に絞り込み、原因となったコミットを特定するためのコマンドです。

|手順|概要|
|---|---|
|1. git bisect start|探索を開始する|
|2. git bisect bad|現在（問題が発生している状態）を「bad」としてマークする|
|3. git bisect good <commit>|問題がなかったことがわかっている過去のコミットを「good」としてマークする|
|4. 二分探索の実行|Gitが自動的に両者の中間のコミットにチェックアウトするので、その時点で動作確認し、`good`/`bad`を都度報告する|
|5. 原因コミットの特定|上記を繰り返すことで、最終的に問題を持ち込んだ最初のコミットが特定される|

多数のコミットの中から手作業で1つずつ確認するのに比べ、対象コミット数を対数オーダ（例：1000コミットでも10回程度の確認）まで減らせる点が大きな利点です。

## タグ

タグは、特定のコミットに対して恒久的な名前を付けるための仕組みです。ブランチと異なり、タグが指す先は通常変化しません。

|種類|概要|
|---|---|
|軽量タグ|単に特定のコミットを指すだけの、シンプルなポインタ|
|注釈付きタグ|作成者、日付、メッセージ、（署名）といった情報を持つ、独立したオブジェクトとして作成されるタグ|

リリースバージョン（`v1.0.0`など）を明示する際によく使われ、`git checkout <tag>`によって、そのバージョン時点のスナップショットを再現できます。
