# TCP/UDP

## トランスポート層の役割

TCPとUDPは、いずれもインターネットプロトコルスイートにおける「トランスポート層」のプロトコルです。IPアドレスによって「どのホストに届けるか」が決まるのに対し、トランスポート層はポート番号によって「同一ホスト内のどのアプリケーション（プロセス）に届けるか」を制御します。

## TCP（Transmission Control Protocol）

TCPは、信頼性の高い通信を実現するためのコネクション型プロトコルです。

|特性|概要|
|---|---|
|コネクション確立|通信開始前に、3ウェイハンドシェイク（SYN → SYN/ACK → ACK）で相手との接続を確立する|
|順序保証|送信したデータが、送信した順序通りに受信側へ届くことを保証する|
|再送制御|パケットの喪失を検知した場合、自動的に再送を行う|
|フロー制御・輻輳制御|受信側の処理能力やネットワークの混雑状況に応じて、送信量を調整する|

これらの信頼性保証の仕組みがある分、UDPと比べてオーバーヘッド（処理コストや遅延）が大きくなります。Webアクセス（HTTP/HTTPS）、メール、ファイル転送など、データの欠落や順序の乱れが許容されない通信の多くでTCPが使われます。

## UDP（User Datagram Protocol）

UDPは、コネクションの確立や信頼性保証を行わない、シンプルで軽量なプロトコルです。

|特性|概要|
|---|---|
|コネクションレス|事前の接続確立を行わず、いきなりデータ（データグラム）を送信する|
|順序保証なし|送信した順序通りに届く保証はない|
|再送制御なし|パケットが失われても、UDP自体は再送を行わない（必要であればアプリケーション側で実装する）|
|低オーバーヘッド|余計な制御を行わない分、TCPより高速でレイテンシが低い|

信頼性よりも速度やリアルタイム性が優先される用途（動画・音声のストリーミング、オンラインゲーム、DNS問い合わせなど）でよく使われます。多少のデータ欠落があっても、通信全体を止めてまで再送するよりも、そのまま処理を続けた方が体験上望ましい場合に適しています。

## 使い分けの考え方

|通信の性質|適したプロトコル|理由|
|---|---|---|
|Webページの表示、ファイルのダウンロード|TCP|データの欠落や順序の乱れが致命的な問題になるため|
|DNSの問い合わせ|UDP（一部TCPも併用）|1回のやり取りが小さく、コネクション確立のコストの方が相対的に大きいため|
|ビデオ通話、オンラインゲーム|UDP|多少のパケットロスより、リアルタイム性（低遅延）が優先されるため|
|QUIC（HTTP/3の基盤）|UDP上に独自の信頼性機構を実装|UDPの低遅延性を活かしつつ、アプリケーション層で必要な信頼性だけを効率的に実装する新しいアプローチ|

近年ではQUICのように、「UDPの上に、TCPが持つような信頼性の仕組みをアプリケーション層で独自に実装する」ことで、両者の利点を組み合わせようとする設計も広がっています。
