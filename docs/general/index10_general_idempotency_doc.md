# 冪等性

## 冪等性とは

冪等性（べきとうせい、Idempotency）とは、「同じ操作を1回行っても、複数回繰り返し行っても、結果が変わらない」という性質を指します。操作を安全に再試行できるかどうかを判断する上で重要な概念です。

|操作例|冪等かどうか|理由|
|---|---|---|
|`x = 5`という代入|冪等|何度実行しても`x`は常に5になる|
|`x = x + 1`という加算|非冪等|実行するたびに`x`の値が変わり続ける|
|ファイルの削除|冪等|2回目の削除は「既に存在しない」という結果になるだけで、状態自体は変わらない（エラーハンドリング次第では非冪等に見えることもある）|
|銀行口座への「1000円振込」|非冪等|同じリクエストを2回送ると、2000円振り込まれてしまう|

## Web APIにおける冪等性

HTTPメソッドは、仕様上それぞれ冪等性が定義されています。これは、通信エラー時に「同じリクエストをそのまま再送してよいか」を判断する重要な基準になります。

|メソッド|冪等性|理由|
|---|---|---|
|GET|冪等|データの取得のみで、状態を変更しない|
|PUT|冪等|同じ内容で「置き換え」を行うため、何度実行しても結果は同じ状態になる|
|DELETE|冪等|同じリソースを2回削除しても、最終的な状態（存在しない）は変わらない|
|POST|非冪等|一般的に「新規作成」を意味するため、実行するたびに新しいリソースが作られてしまう|

「PUTは冪等だからネットワークエラー時に安全に再送できるが、POSTは冪等ではないため安易な再送は二重作成のリスクがある」という判断は、この性質に基づいています。POSTのように本来非冪等な操作を安全に再試行したい場合、後述する冪等キーのような仕組みが使われます。

## インフラ・自動化における冪等性

[宣言的設定](index09_general_declarative&imperative_doc.md)の考え方は、この冪等性と密接に関連しています。TerraformやKubernetesが「あるべき状態」を宣言する方式を採用しているのは、冪等性を保証しやすくするためでもあります。

|ツール|冪等性の表れ方|
|---|---|
|Terraform|`terraform apply`を何度実行しても、既に「あるべき状態」に達していれば、それ以上の変更（差分）は発生しない|
|Kubernetes|同じマニフェストを何度`kubectl apply`しても、クラスタの状態は変わらない（既に望む状態であれば、実質何も起こらない）|
|構成管理ツール（Ansible等）|「パッケージがインストールされているべき」という記述は、既にインストール済みなら何もしない|

これにより、デプロイやインフラ変更のスクリプトが途中で失敗しても、単純に同じ処理を再実行するだけで安全に復旧できる（既に完了している部分は再度実行されても副作用がない）という、運用上非常に重要な性質が得られます。

## 冪等キー（Idempotency Key）

決済APIなど、本来非冪等な操作（POSTによる新規作成）を安全に再試行したい場合に使われる仕組みです。

|項目|概要|
|---|---|
|仕組み|クライアントがリクエストごとに一意なキー（冪等キー）を発行し、リクエストヘッダなどに含めて送信する|
|サーバ側の処理|同じ冪等キーを持つリクエストを既に処理済みであれば、新たに処理を実行せず、前回と同じ結果をそのまま返す|
|典型的な用途|決済処理、送金処理など、「タイムアウトでレスポンスが返ってこなかったが、実際には処理が成功していたかもしれない」場面での安全な再送|

この仕組みにより、本来は非冪等な操作（POST）に対しても、実質的に冪等性と同等の安全な再試行を実現できます。
