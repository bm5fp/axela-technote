# 名前解決（DNS）

## DNSの役割

DNS（Domain Name System）は、人間が読める形式のドメイン名（例：example.com）を、コンピュータが通信に使うIPアドレスに変換する、インターネット規模の分散型データベースです。

## ドメイン名の階層構造

ドメイン名は、右から左に向かって階層的な構造を持っています。

|例|階層|
|---|---|
|`.`（ルート）|全ての階層の頂点。通常は省略される|
|`com`|トップレベルドメイン（TLD）|
|`example.com`|セカンドレベルドメイン|
|`www.example.com`|サブドメイン|

この階層構造により、DNSは単一の巨大な管理主体ではなく、階層ごとに管理を分散させることができています。

## 名前解決の流れ（反復・再帰）

実際にドメイン名からIPアドレスを得るまでには、複数のサーバへの問い合わせが階層をたどるように行われます。

|登場するサーバ|役割|
|---|---|
|スタブリゾルバ|クライアント（PCやスマートフォン）内で動作する、名前解決を要求する最初の窓口|
|フルサービスリゾルバ（キャッシュDNSサーバ）|ユーザからの問い合わせを受け、必要であれば他のDNSサーバに問い合わせを繰り返し、結果をキャッシュして返す（ISPやパブリックDNSが提供）|
|ルートサーバ|「`.com`の情報はこのサーバ群が知っている」というように、TLDの担当サーバを案内する|
|TLDサーバ|「`example.com`の情報はこのサーバが知っている」というように、権威DNSサーバを案内する|
|権威DNSサーバ|そのドメインの実際のレコード（IPアドレスなど）を管理し、最終的な回答を返すサーバ|

|問い合わせの種類|概要|
|---|---|
|再帰的問い合わせ|クライアントがフルサービスリゾルバに対し、「最終的な答えだけを教えてほしい」と依頼する方式|
|反復的問い合わせ|フルサービスリゾルバが、ルート→TLD→権威DNSサーバへと、案内を頼りに自身で順番に問い合わせていく方式|

一度解決された結果は、指定された有効期間（TTL）の間キャッシュされ、同じ問い合わせが繰り返されることによる負荷を軽減します。

## 主なレコードタイプ

DNSサーバが管理する情報は、目的に応じて複数の「レコードタイプ」に分かれています。

|レコード|概要|
|---|---|
|Aレコード|ドメイン名をIPv4アドレスに対応付ける|
|AAAAレコード|ドメイン名をIPv6アドレスに対応付ける|
|CNAMEレコード|あるドメイン名を、別のドメイン名の別名（エイリアス）として定義する|
|MXレコード|そのドメイン宛のメールを処理するメールサーバを指定する|
|TXTレコード|任意のテキスト情報を保持する（ドメイン所有権の確認や、送信ドメイン認証の設定などに使われる）|
|NSレコード|そのドメインの権威DNSサーバがどれかを示す|

## 名前解決に関わるローカルの設定

クライアント側にも、DNSの問い合わせより前に参照される仕組みがあります。

|項目|概要|
|---|---|
|hostsファイル|ドメイン名とIPアドレスの対応を、DNSに問い合わせる前にローカルで直接指定できる静的な設定ファイル|
|ローカルDNSキャッシュ|OS内でDNSの問い合わせ結果を一時的に保持し、同じ問い合わせの重複を避ける仕組み|

多くのOSでは、「hostsファイル → ローカルキャッシュ → 実際のDNS問い合わせ」という優先順位で名前解決が行われるため、開発時に特定のドメイン名を任意のIPアドレスへ一時的に向けたい場合などに、hostsファイルの編集がよく利用されます。
