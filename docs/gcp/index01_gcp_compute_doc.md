# Compute

## Compute Engine

Compute Engineは、GCPが提供するIaaS（Infrastructure as a Service）型の仮想マシンサービスです。OSやミドルウェアを含め、利用者自身が構成をコントロールできる、最も自由度の高いコンピューティングリソースです。

|項目|概要|
|---|---|
|マシンタイプ|CPU/メモリの構成をあらかじめ定義したプリセット（汎用、コンピュート最適化、メモリ最適化など）から選択、またはカスタム構成も可能|
|イメージ|OSやミドルウェアをあらかじめインストールした起動テンプレート。公式イメージに加え、独自のカスタムイメージも作成できる|
|インスタンステンプレート|マシンタイプ・イメージ・ネットワーク設定などをまとめたテンプレート。後述のマネージドインスタンスグループ（MIG）で複製元として使われる|
|マネージドインスタンスグループ（MIG）|同一構成のインスタンス群を管理し、自動スケーリングやヘルスチェックに基づく自動修復（異常なインスタンスの自動再作成）を行う|
|プリエンプティブル/Spot VM|通常より大幅に低コストだが、他の需要に応じて強制的に停止されうる仮想マシン。中断可能なバッチ処理などに向く|

## GKE（Google Kubernetes Engine）

GKEは、GCP上のマネージドKubernetesサービスです。Control Planeの運用をGoogleに任せつつ、コンテナ化されたワークロードを実行できます。詳細はKubernetesドキュメントの各ファイルにある「GKEでの特徴」セクションを参照してください。

|項目|概要|
|---|---|
|Standardモード|Nodeの管理（VM構成やNode Pool）をユーザが行う。柔軟性が高い|
|Autopilotモード|Node管理自体をGoogleに任せ、ワークロードの定義のみに集中できる。Pod単位の課金モデル|

## Cloud Run

Cloud Runは、コンテナイメージをそのままデプロイできる、フルマネージドなサーバレスプラットフォームです。

|項目|概要|
|---|---|
|実行単位|コンテナイメージ（Dockerfileでビルドしたものをそのままデプロイできる）|
|スケーリング|リクエストに応じて自動的にインスタンス数が増減し、リクエストがない時間帯はゼロまでスケールインできる（コールドスタートは発生しうる）|
|課金モデル|実際にリクエストを処理している時間（CPU/メモリ使用量）に応じた従量課金|
|GKEとの違い|Kubernetesのマニフェストやクラスタ管理の知識が不要で、コンテナを用意するだけでHTTPエンドポイントを公開できる手軽さが特徴|

## App Engine

App Engineは、GCP最初期からあるフルマネージドなアプリケーションプラットフォームです。

|環境|概要|
|---|---|
|Standard環境|あらかじめ用意された言語ランタイム上でコードを実行する、より制約の強い（その分スケーリングが高速な）実行環境|
|Flexible環境|Dockerコンテナベースで、より自由度の高い実行環境（Compute Engineの仮想マシン上で動作する）|

Cloud Runの登場以降、コンテナベースの新規ワークロードではCloud Runが選ばれることが多くなっていますが、App Engineは特にStandard環境において、GCPの各種サービス（Datastoreなど）との歴史的な統合や、リクエスト単位でのきめ細かいスケーリングといった特性を持っています。

## サービスの使い分け

|要件|向いているサービス|
|---|---|
|OS・ミドルウェアまで自由に構成したい|Compute Engine|
|複数コンテナの協調動作や高度なオーケストレーションが必要|GKE|
|単一コンテナのHTTPサービスを手軽に公開したい|Cloud Run|
|イベント駆動の小さな関数を実行したい|Cloud Functions（[Serverless&Data](index06_gcp_serverless&data_doc.md)を参照）|

抽象度で並べると「Compute Engine（低レベル・自由度高）→ GKE → Cloud Run → Cloud Functions（高レベル・自由度低だが運用負荷も低い）」という順になり、要件に応じてどこまで管理をGoogleに委ねるかを選択します。
