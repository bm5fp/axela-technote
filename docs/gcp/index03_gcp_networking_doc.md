# Networking

## VPC（Virtual Private Cloud）

VPCは、GCP上に構築する論理的に隔離されたプライベートネットワークです。

|項目|概要|
|---|---|
|グローバルリソース|GCPのVPCは特定のリージョンに縛られず、複数リージョンにまたがるグローバルなリソースとして扱われる（他クラウドとの大きな違いの一つ）|
|サブネット|VPC内をリージョン単位で分割する、実際にIPアドレス範囲が割り当てられる単位|
|ファイアウォールルール|VPC単位で定義する、インスタンス間・外部との通信を許可/拒否するルール|
|限定公開のGoogleアクセス|外部IPを持たないインスタンスから、Cloud StorageなどのGoogle APIへプライベート経路でアクセスできるようにする設定|

## Cloud Load Balancing

Cloud Load Balancingは、GCPが提供するフルマネージドな負荷分散サービスです。

|種別|レイヤ|概要|
|---|---|---|
|グローバル外部HTTP(S)ロードバランサ|L7|世界中のエッジからリクエストを受け付け、最も近いバックエンドにルーティングする|
|リージョン外部/内部ロードバランサ|L4/L7|特定リージョン内での負荷分散|
|内部ロードバランサ|L4/L7|VPC内部からのみアクセス可能な負荷分散（外部に公開しないサービス向け）|

KubernetesのServiceタイプ`LoadBalancer`やIngressリソースを作成すると、内部的にこのCloud Load Balancingのリソースが自動的にプロビジョニングされます（Kubernetesドキュメントの[Networking](../kubernetes/index03_k8s_networking_doc.md)を参照）。

## Cloud DNS

Cloud DNSは、GCPが提供するマネージドDNSサービスです。

|項目|概要|
|---|---|
|パブリックゾーン|インターネットに公開するドメインの名前解決を管理する|
|プライベートゾーン|特定のVPC内でのみ有効な名前解決を管理する（社内向けサービスなど）|
|高い可用性|Googleのグローバルなエニーキャストネットワーク上で動作し、低レイテンシかつ高可用な名前解決を提供する|

## Cloud NAT

Cloud NATは、外部IPアドレスを持たないインスタンスが、インターネットへ向けて通信（アウトバウンド通信）を行うための、マネージドなNAT（Network Address Translation）サービスです。

|項目|概要|
|---|---|
|用途|外部からの直接アクセスは許可したくないが、パッケージの取得など外向きの通信は必要、というインスタンス（プライベートNode等）に使う|
|特徴|NATゲートウェイ自体の可用性やスケーリングをGoogle側が管理するため、自前でNATインスタンスを構築・運用する必要がない|

GKEのプライベートクラスタ（Node自体に外部IPを持たせない構成）では、このCloud NATが、Node上のコンテナがインターネット上のリソース（外部APIやパッケージレジストリなど）にアクセスするための標準的な経路になります。

## サービスの使い分け

|要件|向いているサービス|
|---|---|
|リソース間のネットワーク分離、通信制御|VPC + ファイアウォールルール|
|外部からのトラフィックを複数バックエンドに分散|Cloud Load Balancing|
|ドメイン名の管理|Cloud DNS|
|プライベートインスタンスからの外向き通信|Cloud NAT|
