# Database

## Cloud SQL

Cloud SQLは、MySQL、PostgreSQL、SQL Serverといった、既存のリレーショナルデータベースエンジンをそのままマネージドで提供するサービスです。

|項目|概要|
|---|---|
|運用の肩代わり|バックアップ、パッチ適用、レプリケーション構成、フェイルオーバといった運用作業をGoogle側が肩代わりする|
|高可用性構成|プライマリインスタンスに加えて、別ゾーンにスタンバイインスタンスを構成し、障害時に自動的にフェイルオーバできる|
|リードレプリカ|読み取り専用の複製インスタンスを追加し、参照系の負荷を分散できる|

既存のMySQL/PostgreSQLの知識・ツールがそのまま活用でき、オンプレミスからの移行先としてもよく選ばれます。

## Cloud Spanner

Cloud Spannerは、リレーショナルデータベースの機能（強整合性のトランザクション、SQL）と、NoSQLのような水平スケーラビリティを両立させた、Google独自の分散データベースサービスです。

|項目|概要|
|---|---|
|グローバル分散|複数リージョンにまたがってデータをレプリケーションしつつ、外部整合性（強い一貫性）を保証する|
|スケーラビリティ|ノードを追加することで、単一マシンの限界を超えてスケールアウトできる（Cloud SQLは基本的にスケールアップが中心）|
|コスト|高い可用性・一貫性・スケーラビリティを持つ分、Cloud SQLと比べてコストは高め|

「グローバル規模での強整合性」という、通常はトレードオフになりがちな要件を同時に満たす必要がある場合（金融系のグローバルサービスなど）に選択されます。

## Firestore

Firestoreは、ドキュメント指向のNoSQLデータベースです。

|項目|概要|
|---|---|
|データモデル|JSON的な構造を持つ「ドキュメント」を「コレクション」という単位でグループ化して格納する|
|リアルタイム同期|データの変更をクライアントにリアルタイムに反映できるリスナ機能を持ち、モバイル/Webアプリのバックエンドとしてよく使われる|
|スキーマレス|事前に厳密なスキーマ定義を必要とせず、柔軟にフィールドを追加できる|

リレーショナルデータベースのような複雑なJOINには向きませんが、ドキュメント単位での高速な読み書きやオフライン同期が必要なアプリケーションに適しています。

## BigQuery

BigQueryは、ペタバイト規模のデータに対して高速にSQLクエリを実行できる、サーバレスのデータウェアハウスです。

|項目|概要|
|---|---|
|サーバレス|インスタンスやクラスタのプロビジョニングが不要で、クエリを投げるだけでGoogleが裏側のリソースを自動的に割り当てる|
|列指向ストレージ|大量データの集計・分析クエリに適した列指向（カラムナ）形式でデータを保持する|
|課金モデル|スキャンしたデータ量に応じた従量課金（オンデマンド）、または一定の処理能力を予約する定額課金から選択できる|

トランザクション処理（OLTP）用途のCloud SQL/Spannerとは異なり、BigQueryは分析・集計処理（OLAP）に特化したサービスという位置づけです。

## サービスの使い分け

|要件|向いているサービス|
|---|---|
|既存のMySQL/PostgreSQL資産をそのまま使いたい|Cloud SQL|
|グローバル規模での強整合性・水平スケーラビリティが必須|Cloud Spanner|
|モバイル/Webアプリ向けの柔軟なスキーマ、リアルタイム同期|Firestore|
|大量データに対する分析・集計クエリ|BigQuery|
