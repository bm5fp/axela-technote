# Serverless&Data

## Cloud Functions

Cloud Functionsは、単一の関数単位でデプロイできる、イベント駆動型のサーバレスコンピューティングサービスです。

|項目|概要|
|---|---|
|トリガ|HTTPリクエスト、Cloud Storageへのファイルアップロード、Pub/Subメッセージの受信など、様々なイベントをきっかけに関数を実行できる|
|スケーリング|リクエスト数に応じて自動的にインスタンス数が増減し、未使用時はゼロになる|
|Cloud Runとの違い|Cloud Runがコンテナ単位のデプロイであるのに対し、Cloud Functionsは関数（コードの一部）単位のデプロイであり、より小さな単位・より簡易な記述でイベント処理を実装できる|

## Pub/Sub

Pub/Subは、非同期メッセージングを実現するマネージドサービスです。送信側（Publisher）と受信側（Subscriber）を疎結合にし、システム間の非同期連携を実現します。

|概念|概要|
|---|---|
|トピック|メッセージの送信先となる論理的なチャネル|
|サブスクリプション|トピックに送られたメッセージを受け取るための購読設定。1つのトピックに複数のサブスクリプションを設定し、同じメッセージを複数の受信者に配信することもできる|
|Pull/Push配信|受信側がサブスクリプションからメッセージを取得しにいく方式（Pull）と、Pub/Sub側から受信側のエンドポイントへ能動的に配信する方式（Push）がある|

サービス間の連携において、送信側は受信側の詳細（存在するか、処理が終わったかなど）を意識せずにメッセージを送るだけでよく、システム全体の疎結合化・耐障害性の向上につながります。

## Dataflow

Dataflowは、Apache Beamをベースにした、データのバッチ処理・ストリーム処理を実行するためのフルマネージドサービスです。

|項目|概要|
|---|---|
|Apache Beamベース|バッチ処理（一括処理）とストリーム処理（リアルタイム処理）を、同じプログラミングモデルで記述できる|
|自動スケーリング|処理するデータ量に応じて、実行に使うワーカの数を自動的に増減する|
|典型的なパイプライン|Pub/Subからストリームでデータを受け取り、変換・集計処理を行い、BigQueryに結果を書き込む、といった構成がよく使われる|

## サービスの使い分け

|要件|向いているサービス|
|---|---|
|イベントをきっかけに小さな処理を実行したい|Cloud Functions|
|システム間を疎結合な非同期メッセージングで連携させたい|Pub/Sub|
|大量データに対する変換・集計のパイプラインを構築したい|Dataflow|

典型的なデータ処理基盤では、「Pub/Subでイベントを受け取り、Dataflowで変換・集計し、BigQueryに格納して分析する」というように、これらのサービスを組み合わせて1つのデータパイプラインを構成します。
