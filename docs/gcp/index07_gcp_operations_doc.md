# Operations

GCPのオペレーション系サービス群（旧Stackdriver）は、Cloud Monitoring/Cloud Loggingを中心に、GCP上のリソースやアプリケーションの可観測性を提供します。

## Cloud Monitoring

Cloud Monitoringは、GCPリソースやアプリケーションのメトリクスを収集・可視化し、閾値に基づくアラートを発報するサービスです。

|項目|概要|
|---|---|
|自動収集|Compute Engine、GKE、Cloud SQLなど、多くのGCPサービスのメトリクスがエージェント不要で自動的に収集される|
|カスタムメトリクス|アプリケーション独自の指標を送信し、標準メトリクスと合わせて監視できる|
|ダッシュボード|複数のメトリクスを1画面にまとめて可視化する|
|アラートポリシー|メトリクスが閾値を超えた場合に、メール・Slack・PagerDutyなどへ通知を送る|

## Cloud Logging

Cloud Loggingは、GCPリソースやアプリケーションのログを収集・保存・検索するサービスです。

|項目|概要|
|---|---|
|自動収集|GKEのPodの標準出力/標準エラー出力（Kubernetesドキュメントの[Observability](../kubernetes/index08_k8s_observability_doc.md)を参照）や、Cloud Runのログなどが自動的に取り込まれる|
|ログルータ|条件に応じて、ログをCloud StorageやBigQuery、Pub/Subなど別の宛先に振り分けて転送する|
|ログベースの指標|特定のログパターンの出現回数をメトリクス化し、Cloud Monitoringのアラート対象にできる|

## Cloud Trace

Cloud Traceは、リクエストがサービス間をまたいで処理される際の、レイテンシの内訳を分析する分散トレーシングサービスです。

|項目|概要|
|---|---|
|トレース/スパン|1つのリクエストの全体的な処理の流れ（トレース）と、その中の個々の処理単位（スパン）を記録・可視化する|
|ボトルネックの特定|複数のマイクロサービスをまたぐ処理のうち、どのサービス・どの処理に時間がかかっているかを視覚的に把握できる|
|OpenTelemetryとの連携|標準化された計装（インスツルメンテーション）の仕組みであるOpenTelemetryを使ってアプリケーションにトレースを実装し、その送信先としてCloud Traceを指定できる|

## Error Reporting / Cloud Profiler

|サービス|概要|
|---|---|
|Error Reporting|アプリケーションが出力した例外・エラーを自動的に検出・集約し、頻発するエラーを一覧化する|
|Cloud Profiler|本番環境で稼働中のアプリケーションのCPU・メモリ使用状況を低オーバーヘッドで継続的にプロファイリングし、パフォーマンスのボトルネックを特定する|

## サービスの使い分け

|知りたいこと|使うサービス|
|---|---|
|リソースの使用率、閾値超過時のアラート|Cloud Monitoring|
|何が起きたか（ログの内容そのもの）|Cloud Logging|
|リクエストがどこで遅くなっているか|Cloud Trace|
|どんなエラーが多発しているか|Error Reporting|
|コードのどの処理が重いか|Cloud Profiler|

これらのサービスは個別に使うこともできますが、Cloud Monitoringのダッシュボードから対応するログやトレースへ横断的に遷移できるなど、互いに連携するよう設計されています。
