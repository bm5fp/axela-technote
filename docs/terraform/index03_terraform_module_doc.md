# Module

## モジュールの構造

モジュールは、複数のリソース定義をひとまとまりにして再利用可能にするための単位です。実は、これまで扱ってきた「単一ディレクトリのTerraform構成」自体も、Terraformから見れば「ルートモジュール」という1つのモジュールとして扱われています。

|要素|概要|
|---|---|
|ルートモジュール|`terraform apply`を実行するディレクトリそのもの|
|子モジュール|ルートモジュールから`module`ブロックで呼び出される、別ディレクトリ（またはリモート）に定義されたモジュール|
|入力変数（variable）|モジュールの呼び出し元から値を受け取るためのインターフェース|
|出力値（output）|モジュール内部のリソースの属性を、呼び出し元に返すためのインターフェース|

```hcl
module "vpc" {
  source     = "./modules/vpc"
  cidr_block = "10.0.0.0/16"
}
```

モジュールディレクトリの中身は、通常のTerraform構成と同じく`.tf`ファイル群（variable, resource, output）で構成されます。

## モジュールの再利用と公開（Terraform Registry）

一度作成したモジュールは、複数のプロジェクトや環境で繰り返し呼び出すことができます。

|source指定|概要|
|---|---|
|ローカルパス（`./modules/vpc`）|同一リポジトリ内のモジュールを参照|
|Terraform Registry（`terraform-aws-modules/vpc/aws`）|HashiCorpが運営する公式レジストリで公開されているモジュールを参照|
|Gitリポジトリ（`git::https://...`）|社内Gitなどでホストされたモジュールを直接参照（タグ指定でバージョン固定も可能）|

Terraform Registryには、AWSやGCPの代表的な構成（VPC、EKS/GKEクラスタなど）向けに、コミュニティやHashiCorp公認のモジュールが数多く公開されており、車輪の再発明を避けて堅牢な構成をすぐに利用できます。

## モジュール間の依存関係

複数のモジュールを組み合わせて1つのインフラを構築する場合、あるモジュールの出力値を別のモジュールの入力値として渡すことで、モジュール間の依存関係を表現します。

```hcl
module "vpc" {
  source = "./modules/vpc"
}

module "ec2" {
  source    = "./modules/ec2"
  subnet_id = module.vpc.subnet_id
}
```

このように`module.<モジュール名>.<出力名>`という形式で他モジュールの出力を参照すると、Terraformは内部的に依存関係グラフを構築し、`vpc`モジュールのリソースが先に作成されてから`ec2`モジュールが作成されるよう、自動的に実行順序を決定します。

モジュールを適切に分割することで、「ネットワーク層」「コンピュート層」「データベース層」のように責務ごとにインフラを整理でき、変更の影響範囲を局所化しやすくなります。
