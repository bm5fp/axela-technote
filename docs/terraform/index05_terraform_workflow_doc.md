# Workflow

Terraformの基本的な運用は、以下4つのコマンドを中心とした一連の流れで進みます。

## terraform init

作業ディレクトリを初期化するコマンドです。Terraformで何らかの操作を行う前に、最初に必ず実行する必要があります。

|処理内容|概要|
|---|---|
|Providerのダウンロード|`required_providers`で指定されたProviderプラグインを、Terraform Registryなどから取得し`.terraform/`ディレクトリに配置する|
|モジュールの取得|`module`ブロックで参照しているローカル/リモートモジュールを取得する|
|バックエンドの初期化|`backend`ブロックの設定に基づき、Stateの保存先（リモートバックエンド）に接続する|
|依存関係のロック|取得したProviderのバージョンを`.terraform.lock.hcl`に記録し、以降の実行で同じバージョンが使われることを保証する|

構成ファイルにProviderの追加やバックエンドの変更を行った場合は、再度`terraform init`を実行する必要があります。

## terraform plan

現在のコード（あるべき状態）と、Stateファイル・実際のインフラ（現在の状態）を比較し、「何を作成・変更・削除するか」という実行計画を表示するコマンドです。実際のインフラには一切変更を加えません。

|出力記号|意味|
|---|---|
|+|リソースの新規作成|
|-|リソースの削除|
|~|リソースの変更（既存のまま更新）|
|-/+|リソースの再作成（一度削除してから作り直す。既存リソースの特定属性は変更不可のため発生することがある）|

`terraform plan -out=tfplan`のように結果をファイルに保存し、続く`apply`でそのファイルを指定することで、「planで確認した内容と、applyで実際に適用される内容が完全に一致する」ことを保証できます。

## terraform apply

`plan`で計算された実行計画を、実際のインフラに適用するコマンドです。デフォルトでは、適用前に変更内容を表示し、ユーザに確認（`yes`の入力）を求めます。

|オプション|概要|
|---|---|
|-auto-approve|確認プロンプトをスキップする（CI/CDパイプラインでの自動実行時によく使われる）|
|tfplanファイルの指定|`terraform apply tfplan`のように、事前に保存したplan結果をそのまま適用する|

apply実行後、Terraformは変更結果をStateファイルに反映し、以降の差分計算の基準を更新します。

## terraform destroy

構成ファイルで定義されている全リソースを削除するコマンドです。`-target`オプションで特定のリソースのみを対象にすることもできますが、依存関係の整合性が崩れる可能性があるため慎重な利用が求められます。

検証環境の使い捨てや、プロジェクト終了時のリソース一括削除など、明示的に「インフラ全体を破棄したい」場面で使用します。本番環境では誤操作による重大な影響を避けるため、`destroy`の実行に追加の承認フローを設けることが一般的です。
