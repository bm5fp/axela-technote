# Package

## パッケージマネージャ（apt, yum/dnf, pacmanなど）

パッケージマネージャは、ソフトウェアのインストール・更新・削除と、それに伴う依存関係の解決を自動化するツールです。Linuxディストリビューションの系統ごとに異なる実装が使われています。

|系統|パッケージ形式|主なコマンド|代表的ディストリビューション|
|---|---|---|---|
|Debian系|.deb|apt, apt-get, dpkg|Debian, Ubuntu|
|Red Hat系|.rpm|dnf, yum, rpm|RHEL, CentOS, Fedora|
|Arch系|独自形式|pacman|Arch Linux|

|コマンド例（apt）|役割|
|---|---|
|apt update|パッケージリスト（メタデータ）の更新|
|apt install <pkg>|パッケージのインストール|
|apt upgrade|インストール済みパッケージの更新|
|apt remove / purge|パッケージの削除（purgeは設定ファイルも含めて削除）|
|apt search|パッケージの検索|

`apt`や`dnf`のような高レベルツールはリモートのリポジトリと通信し依存関係を自動解決するのに対し、`dpkg`や`rpm`は個々のパッケージファイル（.deb, .rpm）を直接操作する低レベルツールという役割分担になっています。

コンテナイメージ（Dockerfile）のビルド時にも、これらのパッケージマネージャを用いて必要なライブラリやツールをイメージに含めることが一般的です。

## 依存関係解決の仕組み

多くのソフトウェアは、単体では動作せず、他のライブラリやツール（依存パッケージ）を必要とします。パッケージマネージャは、この依存関係を自動的に解決し、必要なパッケージ群を過不足なくインストールします。

|概念|概要|
|---|---|
|依存関係（Depends）|そのパッケージが動作するために必須となる他のパッケージ|
|推奨（Recommends）|必須ではないが、通常は一緒にインストールされることが望ましいパッケージ|
|競合（Conflicts）|同時にインストールできない、あるいは問題を起こすパッケージの組み合わせ|
|バージョン制約|「バージョンX以上」のように、依存先パッケージのバージョン範囲を指定する仕組み|

依存関係の情報は、リポジトリが提供するメタデータ（例：aptの`Packages`ファイル）に記述されており、`apt update`などで取得したこのメタデータをもとに、パッケージマネージャは「必要なパッケージ群を、競合なくインストールするための組み合わせ」を計算します。

依存関係が複雑化し解決不能になる状態は「依存地獄（dependency hell）」と呼ばれることがあり、これを回避するアプローチとして、依存関係をパッケージ内に完全に同梱する形式（Docker、Snap、Flatpak、AppImageなど）も広く使われるようになっています。コンテナ技術がアプリケーションの配布において重視される理由の一つも、まさにこの「実行環境に依存しない、自己完結したパッケージング」を実現できる点にあります。
