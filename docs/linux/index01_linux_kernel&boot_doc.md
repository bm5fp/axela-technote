# カーネルとブート

## カーネルアーキテクチャ（モノリシック vs マイクロカーネル）

カーネルはOSの中核であり、プロセス管理・メモリ管理・デバイス制御・ファイルシステム・ネットワークなど、ハードウェアとアプリケーションの橋渡しを行う部分です。
その内部設計には大きく分けて2つの方式があります。

|方式|特徴|代表例|
|---|---|---|
|モノリシックカーネル|プロセス管理・ファイルシステム・デバイスドライバなど全機能を1つの大きなカーネル空間内で実行する|Linux|
|マイクロカーネル|カーネルには最小限の機能（プロセス間通信・スケジューリングなど）のみを置き、ドライバやファイルシステムはユーザ空間で動作させる|Minix, QNX|

Linuxはモノリシックカーネルに分類されますが、カーネルモジュールという仕組みにより、必要な機能を動的にロード/アンロードできる柔軟性を持っています。
そのため「モノリシックだが、モジュール化された設計」とも言われます。

なお、カーネルはメモリ上で「カーネル空間」と呼ばれる特権的な領域で動作し、通常のアプリケーションが動作する「ユーザ空間」とは明確に分離されています。
ユーザ空間からカーネル空間の機能を利用する際は、システムコールという決められた窓口を経由します。

## ブートプロセス（BIOS/UEFI → ブートローダ(GRUB) → カーネル → init）

Linuxマシンの電源投入からログイン画面が表示されるまでには、以下のような段階を経ます。

1. **BIOS/UEFI**：マザーボード上のファームウェア。ハードウェアの初期診断（POST）を行い、起動可能なデバイス（ブートローダ）を探して制御を渡す。UEFIはBIOSの後継規格で、GPTパーティションやSecure Bootに対応する。
2. **ブートローダ（GRUB等）**：ディスク上のどのカーネルを、どのオプション（カーネルパラメータ）付きで起動するかを選択し、カーネルをメモリにロードする。複数のカーネルバージョンやOSを選択できるメニューも提供する。
3. **カーネルの起動**：ロードされたカーネルが展開され、ハードウェアの初期化、ルートファイルシステムのマウント準備を行う。この際、initramfs（一時的な初期RAMファイルシステム）を利用して、本来のルートファイルシステムをマウントするために必要なドライバ等を先に読み込むことが多い。
4. **initプロセスの起動**：カーネルが最初に起動するユーザ空間プロセス（PID 1）。以降、必要なサービスやデーモンを順次起動し、ログイン可能な状態まで持っていく。

## initシステム（systemd, SysVinit）

initはOS起動時に最初に起動するプロセス（PID 1）で、システム全体のサービス起動・管理を担います。歴史的にいくつかの方式が存在します。

|init方式|特徴|
|---|---|
|SysVinit|ランレベル（0〜6）ごとにシェルスクリプトを順次実行する古典的な方式。処理が直列的で起動が遅い|
|Upstart|イベント駆動でサービスを起動する過渡的な方式（現在はほぼ使われない）|
|systemd|現在主流。並列起動やユニット間の依存関係管理により高速化・信頼性向上を実現|

systemdでは「ユニット」という単位でサービスやデバイス、マウントポイントなどを管理します。

|ユニット種別|拡張子|役割|
|---|---|---|
|Service|.service|デーモンなどの起動・停止を定義|
|Target|.target|複数ユニットをまとめるグループ（SysVinitのランレベルに相当）|
|Mount|.mount|ファイルシステムのマウント定義|
|Timer|.timer|cronのような定期実行の定義|

主なコマンドは `systemctl start/stop/status <service>`、ログ確認は `journalctl` を利用します。

## カーネルモジュール（insmod, modprobe, /lib/modules）

カーネルモジュールは、カーネル本体を再コンパイル・再起動することなく、機能（主にデバイスドライバやファイルシステムドライバ）を動的に追加・削除できる仕組みです。

|コマンド|役割|
|---|---|
|lsmod|現在ロードされているモジュール一覧を表示|
|insmod|指定したモジュールファイル(.ko)を直接ロード（依存関係は解決しない）|
|modprobe|依存関係を自動解決しつつモジュールをロード/アンロード|
|rmmod|モジュールをアンロード|

モジュール本体は `/lib/modules/<カーネルバージョン>/` 配下に格納されており、`modprobe` はこの配下と依存関係情報（`modules.dep`）を参照して必要なモジュールを芋づる式にロードします。

これにより、例えば特定のUSBデバイスを接続した際に、対応するドライバモジュールが自動的にロードされるといった動作が実現されています。

## カーネルパラメータ（sysctl, /proc/sys）

Linuxカーネルは、多くの動作パラメータを実行中に変更できるインターフェースを提供しています。これらのパラメータは `/proc/sys` 以下に仮想的なファイルとして表現されており、読み書きすることで即座にカーネルの挙動を変更できます。

|操作|コマンド例|
|---|---|
|現在値の確認|`cat /proc/sys/net/ipv4/ip_forward`|
|一時的な変更|`sysctl -w net.ipv4.ip_forward=1`|
|恒久的な変更|`/etc/sysctl.conf` や `/etc/sysctl.d/*.conf` に記載し `sysctl -p` で反映|
|全パラメータ一覧|`sysctl -a`|

代表的なパラメータ例：

|パラメータ|概要|
|---|---|
|net.ipv4.ip_forward|IPフォワーディング（ルーティング）の有効化|
|vm.swappiness|スワップの使用しやすさ（0〜100）|
|fs.file-max|システム全体でオープンできるファイル数の上限|
|kernel.pid_max|割り当て可能なPIDの最大値|
