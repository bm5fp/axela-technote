# Network

## ネットワークインターフェースと設定

ネットワークインターフェースは、Linuxがネットワーク通信を行うための入出力口（物理NICや仮想的なもの）です。

|インターフェース例|概要|
|---|---|
|eth0, ens160など|物理的なイーサネットインターフェース|
|lo|ループバックインターフェース（自ホスト宛通信、127.0.0.1）|
|vethペア|仮想イーサネット。コンテナとホストを繋ぐトンネルとして機能する|
|br0|ブリッジインターフェース。複数のインターフェースをL2で束ねる|

|コマンド|役割|
|---|---|
|ip addr|IPアドレスの確認・設定|
|ip link|インターフェースの有効化/無効化、状態確認|
|ethtool|物理NICの詳細設定（リンク速度など）|
|nmcli|NetworkManager経由での設定管理|

近年は伝統的な `ifconfig` に代わり、`iproute2` パッケージの `ip` コマンドが標準的に使われています。

## ルーティングテーブル

ルーティングテーブルは、パケットの宛先IPアドレスに応じて「どのインターフェースから」「どのネクストホップ（次の転送先）へ」送るかを決定するための表です。

|コマンド|役割|
|---|---|
|ip route show|現在のルーティングテーブルを表示|
|ip route add|静的ルートの追加|
|ip route del|ルートの削除|

代表的なエントリに「デフォルトゲートウェイ」があり、これはルーティングテーブル中のどのルールにも一致しなかったパケットの転送先を示します。

## ソケットとポート

ソケットは、プロセスがネットワーク通信を行うためのプログラミング上の抽象化されたエンドポイントです。IPアドレスとポート番号の組み合わせによって、通信相手（サービス）を一意に特定します。

|概念|概要|
|---|---|
|ポート番号|0〜65535の番号。同一ホスト上の複数サービスを識別する|
|ウェルノウンポート|0〜1023。特権が必要（HTTPの80、HTTPSの443、SSHの22など）|
|TCPソケット|コネクション型。信頼性のある順序保証された通信（HTTP、SSHなど）|
|UDPソケット|コネクションレス型。高速だが信頼性は呼び出し側で担保する必要がある（DNS、動画配信など）|

|コマンド|役割|
|---|---|
|ss / netstat|現在開いているソケット・ポートの一覧表示|
|lsof -i|ポートを利用しているプロセスの特定|

## netfilter / iptables / nftables

netfilterは、Linuxカーネル内に組み込まれたパケットフィルタリング・変換のためのフレームワークです。パケットがネットワークスタックを通過する各段階（フック）に処理を挟み込むことができます。

|ツール|概要|
|---|---|
|iptables|netfilterを操作する伝統的なコマンド。ルールを「チェーン」という単位で管理する|
|nftables|iptablesの後継。より高速かつ柔軟な構文で書ける新しいフレームワーク|

|iptablesの主なチェーン|タイミング|
|---|---|
|PREROUTING|パケット到着直後、ルーティング判断前|
|INPUT|自ホスト宛のパケット|
|FORWARD|他ホストへ転送されるパケット|
|OUTPUT|自ホストから送信されるパケット|
|POSTROUTING|ルーティング判断後、送信直前|

用途としては、ファイアウォール（特定ポートの許可/拒否）に加え、NAT（アドレス変換）にも利用されます。

## DNS解決の仕組み

DNS（Domain Name System）は、人が読めるホスト名（例：example.com）をIPアドレスに変換する仕組みです。Linux上での名前解決は、複数のファイル・コンポーネントが連携して行われます。

|要素|役割|
|---|---|
|/etc/hosts|静的なホスト名とIPの対応表。DNSより優先されることが多い|
|/etc/resolv.conf|問い合わせ先のDNSサーバ（ネームサーバ）を指定|
|/etc/nsswitch.conf|名前解決の際に、どの情報源（files, dns等）をどの順番で参照するか定義|
|getent hosts|実際の名前解決結果を確認するコマンド|

問い合わせの流れは、通常「スタブリゾルバ（アプリケーションが呼び出すライブラリ関数）→ローカルDNSキャッシュ（systemd-resolvedなど）→再帰的な問い合わせを行うDNSサーバ→権威DNSサーバ」という順に進みます。

## ネットワーク名前空間（コンテナ技術の基盤）

ネットワーク名前空間（Network Namespace）は、Linuxカーネルのnamespace機能の一種で、ネットワークインターフェース・ルーティングテーブル・iptablesルール・ポート空間などを、他のプロセス群から完全に分離する仕組みです。

|分離される要素|概要|
|---|---|
|インターフェース|名前空間ごとに独立したNIC（仮想含む）を持てる|
|ルーティングテーブル|名前空間ごとに別々の経路情報を持てる|
|ポート空間|異なる名前空間であれば、同じポート番号を別プロセスが使い回せる|

コンテナ技術は、コンテナごとに独立したネットワーク名前空間を割り当てることで「コンテナはそれぞれ独立したネットワークスタックを持つ」ように見せています。ホストとコンテナ間、あるいはコンテナ同士は、veth（仮想イーサネットペア）やブリッジを介して接続されます。
