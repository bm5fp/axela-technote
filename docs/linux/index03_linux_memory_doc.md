# Memory

## 仮想メモリとページング

Linuxを含む現代のOSでは、プロセスは物理メモリのアドレスを直接扱わず、「仮想アドレス空間」という抽象化された独自のメモリ空間を持ちます。
カーネルはMMU（Memory Management Unit）というCPU上のハードウェア機能と連携し、仮想アドレスを実際の物理アドレスに変換（マッピング）します。

この仕組みにより、以下のメリットが得られます。

- 各プロセスは他プロセスのメモリを直接参照できず、メモリ空間が分離される（セキュリティ・安定性の向上）
- 物理メモリより大きなアドレス空間をプロセスに見せることができる（後述のスワップと組み合わせる）
- 物理メモリ上の空き領域を柔軟に割り当てられる（断片化した物理メモリでも連続した仮想アドレスとして扱える）

仮想メモリは固定長の「ページ」（通常4KB）単位で管理され、仮想ページと物理ページの対応関係は「ページテーブル」に記録されます。この方式を「ページング」と呼びます。

## スワップ

物理メモリ（RAM）が不足した際に、使用頻度の低いメモリ内容を一時的にディスク上の「スワップ領域」に退避させ、空いた物理メモリを他のプロセスに割り当てる仕組みです。

|項目|内容|
|---|---|
|スワップイン|スワップ領域からデータを物理メモリに戻すこと|
|スワップアウト|物理メモリの内容をスワップ領域に退避すること|
|swappiness|スワップの積極性を示すカーネルパラメータ（0〜100、大きいほどスワップされやすい）|

スワップはディスクI/Oを伴うため、物理メモリへのアクセスと比べて非常に低速です。スワップが頻発する状態（スラッシング）は、システム全体のパフォーマンス低下を招きます。

## ページキャッシュ / バッファキャッシュ

Linuxカーネルは、ディスクI/Oのパフォーマンスを向上させるため、一度読み書きしたディスク上のデータを積極的にメモリ上にキャッシュします。

|種類|概要|
|---|---|
|ページキャッシュ|ファイルの内容（読み書きされたデータ）をページ単位でメモリにキャッシュする|
|バッファキャッシュ|ディスクのブロック単位の入出力（メタデータなど）をキャッシュする（現在はページキャッシュに統合される形で実装されている）|

`free` コマンドで表示される `buff/cache` はこれらのキャッシュ使用量を示します。このメモリは、アプリケーションが追加のメモリを必要とした場合にはすぐに解放できる「利用可能なメモリ」として扱われるため、`free` コマンドの `available` 列を見ることが、実際に空いているメモリ量を把握する上で重要です。

## OOM Killer

OOM（Out Of Memory）Killerは、システム全体の物理メモリとスワップが枯渇し、これ以上メモリを確保できなくなった際に、カーネルが強制的に特定のプロセスを終了させてメモリを回収する仕組みです。

カーネルは各プロセスに対して「OOMスコア」を計算し、スコアが高い（＝終了させても影響が少なそうな）プロセスから順にkillします。
スコアは `/proc/[PID]/oom_score` で確認でき、`/proc/[PID]/oom_score_adj` を調整することでkillされやすさを変更できます。

## メモリマッピング（mmap）

`mmap()` システムコールは、ファイルやデバイスの内容を、プロセスの仮想アドレス空間に直接マッピングする仕組みです。これにより、ファイルの読み書きを、通常のメモリ操作と同じように行うことができます。

|用途|概要|
|---|---|
|ファイルの高速な読み書き|read/writeによる都度のシステムコール呼び出しを避け、メモリアクセスとして扱える|
|共有メモリの実現|複数プロセスが同じファイル（または匿名メモリ領域）をmmapすることで、メモリを共有できる|
|動的ライブラリのロード|実行ファイルが共有ライブラリ（.so）を読み込む際にも内部的に利用される|

mmapされた領域は、必要になった時点で初めて実際にディスクから読み込まれる「デマンドページング」という遅延読み込みの仕組みで動作するため、大きなファイルでも効率的に扱うことができます。
