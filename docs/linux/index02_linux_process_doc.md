# Process

## プロセスとスレッドの違い

プロセスは、実行中のプログラムの単位であり、独立したメモリ空間（アドレス空間）・ファイルディスクリプタ・PIDを持ちます。
スレッドは、プロセス内で動作する実行の単位であり、同一プロセス内の複数のスレッドはメモリ空間を共有します。

|項目|プロセス|スレッド|
|---|---|---|
|メモリ空間|独立|同一プロセス内で共有|
|生成コスト|高い（アドレス空間のコピーが必要）|低い|
|通信手段|IPC（パイプ、ソケット等）が必要|共有メモリを直接参照できる|
|障害影響|他プロセスに影響しにくい|同一プロセス内の他スレッドに影響しうる|

Linuxでは、プロセスもスレッドも `task_struct` というカーネル内部の構造体で管理されており、`clone()` システムコールに渡すフラグの違いによって「プロセスとして生成するか」「スレッドとして生成するか」が決まります。

## プロセスライフサイクル（fork, exec, wait, exit）

Linuxで新しいプロセスを生成する基本的な流れは、以下のシステムコールの組み合わせで実現されます。

|システムコール|役割|
|---|---|
|fork()|呼び出し元プロセス（親）のコピーを子プロセスとして生成する|
|exec()系|現在のプロセスのメモリイメージを別のプログラムで置き換える|
|wait()/waitpid()|子プロセスの終了を待ち、終了ステータスを回収する|
|exit()|プロセスを終了し、終了コードをカーネルに通知する|

典型的なシェルのコマンド実行は「シェルプロセスが `fork()` で子プロセスを複製し、子プロセス側で `exec()` により目的のプログラムに置き換わり、親プロセスは `wait()` で子の終了を待つ」という流れになります。

子プロセスが終了したにもかかわらず、親プロセスが `wait()` を呼ばず終了ステータスを回収しない状態を「ゾンビプロセス」と呼びます。

## プロセス状態（実行中/スリープ/ゾンビ/停止）

プロセスは、その時々の状況に応じて複数の状態のいずれかを取ります。`ps` コマンドの `STAT` 列などで確認できます。

|状態|記号|概要|
|---|---|---|
|実行中/実行可能（Running/Runnable）|R|CPUを使用中、またはスケジューラの順番待ち|
|割り込み可能なスリープ（Sleeping）|S|I/O待ちなど。シグナルで起床可能|
|割り込み不可能なスリープ|D|ディスクI/O等の完了待ち。シグナルでも中断されない|
|停止（Stopped）|T|SIGSTOPなどにより一時停止中|
|ゾンビ（Zombie）|Z|プロセス自体は終了済みだが、親がwait()で回収していない状態|

ゾンビプロセスはメモリやCPUをほぼ消費しませんが、大量に蓄積するとPIDテーブルを圧迫する可能性があります。

## シグナル（SIGKILL, SIGTERM, SIGHUPなど）

シグナルは、プロセスに対して非同期にイベントを通知する仕組みです。カーネルやOSの他プロセス、あるいは自プロセスから送信されます。

|シグナル|番号|概要|
|---|---|---|
|SIGHUP|1|端末切断、または設定再読み込みの慣習的な合図|
|SIGINT|2|Ctrl+Cによる割り込み|
|SIGKILL|9|強制終了。プロセス側でハンドリング・無視は不可能|
|SIGTERM|15|終了要求。プロセスがハンドラで後片付け処理を行うことができる（デフォルトのkillコマンドが送るシグナル）|
|SIGSTOP|19|強制的な一時停止。無視不可|
|SIGCONT|18|停止したプロセスの再開|

`kill -9 <PID>` はSIGKILLを送る操作であり、プロセスに後片付けの猶予を与えません。そのため、まずはSIGTERM（`kill <PID>`）で正常終了を試み、応答がない場合の最終手段としてSIGKILLを使うのが一般的な運用です。

## プロセス間通信（IPC）（パイプ, ソケット, 共有メモリ, セマフォ, メッセージキュー）

異なるプロセス間でデータをやり取りするための仕組みです。

|方式|概要|
|---|---|
|パイプ（pipe）|`\|` で繋ぐような、片方向のデータストリーム。名前なし（無名）パイプは親子プロセス間などに限定される|
|名前付きパイプ（FIFO）|ファイルシステム上に実体を持ち、無関係なプロセス間でも利用可能|
|ソケット（Unix domain socket/TCP等）|同一ホスト内、またはネットワーク越しの双方向通信|
|共有メモリ（shared memory）|複数プロセスが同一の物理メモリ領域を直接参照。最も高速だが同期制御が別途必要|
|セマフォ（semaphore）|共有リソースへの同時アクセス数を制御するためのカウンタ|
|メッセージキュー（message queue）|構造化されたメッセージ単位でのやり取りをカーネルが仲介|

コンテナ間通信の文脈では、Unix domain socketやTCPソケットが多用されます（例：Dockerデーモンとの通信は `/var/run/docker.sock` というUnix domain socket経由）。

## スケジューリング（CFS, nice値, リアルタイムスケジューリング）

Linuxカーネルは、複数のプロセスにCPU時間を公平かつ効率的に割り当てるスケジューラを持ちます。

- **CFS（Completely Fair Scheduler）**：通常のプロセス（SCHED_OTHER）向けのデフォルトスケジューラ。各プロセスの「仮想実行時間」を管理し、最も実行時間が少ないプロセスを優先的に実行することで、CPU時間を公平に分配する。
- **nice値**：プロセスの実行優先度を示す値（-20〜19）。値が小さいほど優先度が高い。`nice`/`renice` コマンドで変更可能。ただしCFSでは優先度は「重み付け」として働き、低優先度プロセスが完全に飢餓状態になるわけではない。
- **リアルタイムスケジューリング**：SCHED_FIFOやSCHED_RRといったポリシーを用い、通常プロセスより優先してCPUを割り当てる。厳密な応答時間が求められる用途（産業制御など）向け。

## /procファイルシステムによるプロセス情報

`/proc` は、カーネル内部の情報をファイルのように参照できる仮想ファイルシステムです。実際にディスクに保存されているわけではなく、アクセス時にカーネルが動的に内容を生成します。

|パス|内容|
|---|---|
|/proc/[PID]/status|プロセスの状態、メモリ使用量など|
|/proc/[PID]/cmdline|起動時のコマンドライン引数|
|/proc/[PID]/fd/|オープン中のファイルディスクリプタ一覧|
|/proc/[PID]/cgroup|所属するcgroupの情報|
|/proc/meminfo|システム全体のメモリ情報|
|/proc/cpuinfo|CPU情報|

`ps` や `top` などのコマンドは、内部的にこの `/proc` 配下の情報を読み取って表示しています。
