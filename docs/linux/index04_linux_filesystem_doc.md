# FileSystem

## ファイルシステム階層標準（FHS）

FHS（Filesystem Hierarchy Standard）は、Linuxディストリビューション間でディレクトリ構成を統一するための標準規格です。これにより、どのディストリビューションでも似たような場所に同種のファイルが配置されます。

|ディレクトリ|用途|
|---|---|
|/bin, /usr/bin|一般ユーザ向けの実行コマンド|
|/sbin, /usr/sbin|システム管理者向けの実行コマンド|
|/etc|システム全体の設定ファイル|
|/home|一般ユーザのホームディレクトリ|
|/var|ログやキャッシュなど、頻繁に変化するデータ|
|/tmp|一時ファイル（再起動で消えることが多い）|
|/proc|プロセス・カーネル情報を表す仮想ファイルシステム|
|/dev|デバイスファイル|
|/lib, /usr/lib|共有ライブラリ|
|/opt|サードパーティ製アプリケーション|

近年のディストリビューションでは `/bin` や `/sbin` が `/usr/bin` へのシンボリックリンクになっている（usrマージ）など、統合が進んでいます。

## inodeとディレクトリエントリ

Linuxのファイルシステムでは、ファイルの実体（データ本体とメタデータ）を管理する「inode」と、ファイル名とinodeを対応付ける「ディレクトリエントリ」が分離しています。

|要素|保持する情報|
|---|---|
|inode|ファイルサイズ、パーミッション、所有者、タイムスタンプ、データブロックへのポインタなど（ファイル名は含まない）|
|ディレクトリエントリ|ファイル名 と inode番号 の対応関係|

この分離により、同一のinode（実体）に対して複数の名前（ハードリンク）を割り当てることが可能になっています。`ls -i` でファイルのinode番号を、`stat` コマンドでinodeの詳細情報を確認できます。

inodeの総数はファイルシステム作成時に決まるため、小さなファイルを大量に作成するとディスク容量に余裕があっても「inode不足」でファイルが作成できなくなることがあります（`df -i` で確認可能）。

## ハードリンク vs シンボリックリンク

同じファイルを複数の場所から参照する仕組みとして、2種類のリンクがあります。

|項目|ハードリンク|シンボリックリンク（symlink）|
|---|---|---|
|実体|同一inodeを直接指す|リンク先のパス文字列を保持する別ファイル|
|ファイルシステムをまたぐ|不可|可能|
|ディレクトリへのリンク|通常不可|可能|
|元ファイル削除時|リンク先が有効な限りデータは残る（inodeの参照カウントが0になって初めて解放）|リンク切れ（実体が消えると無効なリンクになる）|
|作成コマンド|`ln 元 リンク名`|`ln -s 元 リンク名`|

ハードリンクは実体を共有する「同格の別名」であるのに対し、シンボリックリンクはパスへの「参照（ショートカット）」である点が本質的な違いです。

## マウントとファイルシステムの種類（ext4, xfs, btrfs, overlayfs, tmpfsなど）

Linuxでは、ディスクパーティションやリムーバブルメディア、あるいは特殊なファイルシステムを、ディレクトリツリー上の任意の場所に「マウント」して利用します。

|ファイルシステム|特徴|
|---|---|
|ext4|Linuxで長く使われる標準的なファイルシステム。安定性が高い|
|xfs|大容量・高並列I/Oに強い。RHEL系でよく標準採用される|
|btrfs|スナップショットや透過的圧縮など高度な機能を持つ次世代ファイルシステム|
|overlayfs|複数のディレクトリ（レイヤ）を重ね合わせて1つのファイルシステムに見せる。Dockerのイメージレイヤ管理で利用される|
|tmpfs|メモリ（RAM）上に作られる一時ファイルシステム。再起動で消える。`/dev/shm`など|

主なコマンド：`mount`（マウント）、`umount`（アンマウント）、`/etc/fstab`（起動時に自動マウントする設定ファイル）、`df -T`（マウント状況とファイルシステム種別の確認）。

## パーミッションと所有権（rwx, chmod, chown, umask）

Linuxのファイルには、「誰が」「何をできるか」を制御するパーミッション（許可）情報が付与されています。

|区分|意味|
|---|---|
|所有者（Owner/User）|ファイルを作成した、または割り当てられたユーザ|
|グループ（Group）|所有グループに属するユーザ|
|その他（Others）|上記以外の全ユーザ|

各区分に対して、以下3種の権限が設定されます。

|権限|記号|ファイルでの意味|ディレクトリでの意味|
|---|---|---|---|
|読み取り|r|内容の閲覧|ファイル一覧の取得|
|書き込み|w|内容の変更|ファイルの作成・削除|
|実行|x|プログラムとして実行|ディレクトリへの移動（cd）|

`ls -l` の先頭に表示される `-rwxr-xr--` のような文字列がこれに該当し、`chmod 754 file` のように数値（各3ビットの組み合わせ）でも指定できます。

|コマンド|役割|
|---|---|
|chmod|パーミッションの変更|
|chown|所有者・所有グループの変更|
|umask|新規作成ファイルのデフォルトパーミッションから差し引く値を設定|

## ACL（アクセス制御リスト）

従来の所有者/グループ/その他という3区分だけでは、「特定の複数ユーザにだけ個別の権限を与えたい」といった細かい制御ができません。ACL（Access Control List）は、この制約を超えて、任意のユーザ・グループ単位で個別の権限を追加設定できる仕組みです。

|コマンド|役割|
|---|---|
|getfacl|ファイルのACL設定を確認|
|setfacl -m u:user1:rw file|user1に対してrw権限を追加|
|setfacl -m g:group1:r file|group1に対してr権限を追加|

ACLが設定されているファイルは、`ls -l` のパーミッション表示の末尾に `+` が付与されることで識別できます。ACLを利用するには、ファイルシステムがACLに対応している必要があります（ext4, xfsなどは標準対応）。

## 特殊権限（SUID, SGID, Sticky Bit）

通常のrwx権限に加えて、特別な意味を持つ3つのビットが存在します。

|特殊権限|付与対象|効果|
|---|---|---|
|SUID（Set User ID）|実行ファイル|実行時に、実行者ではなく「ファイルの所有者」の権限で動作する（例：passwdコマンドが一般ユーザでも/etc/shadowを書き換えられる理由）|
|SGID（Set Group ID）|実行ファイル/ディレクトリ|実行ファイルの場合はファイルの所有グループ権限で動作。ディレクトリの場合、その配下に作成されるファイルが親ディレクトリと同じグループを継承する|
|Sticky Bit|主にディレクトリ|そのディレクトリ内のファイルは、たとえ書き込み権限があっても「所有者かrootしか削除・改名できない」（例：/tmp）|

`chmod` では、これらは4桁目の数値（SUID=4, SGID=2, Sticky=1）またはシンボリックモード（`chmod u+s`, `chmod g+s`, `chmod +t`）で設定します。`ls -l` では、実行権限の位置が `s` や `t` に置き換わって表示されます。

SUIDが設定された不要な実行ファイルは権限昇格の脆弱性につながる可能性があるため、セキュリティ監査では `find / -perm -4000` のようなコマンドでSUID付きファイルを洗い出すことがよく行われます。
