# Shell

## シェルの種類（bash, zsh, shなど）

シェルは、ユーザが入力したコマンドを解釈し、カーネルに処理を依頼するインターフェースとなるプログラムです。Linuxには複数の実装があり、それぞれ機能や利便性に違いがあります。

|シェル|概要|
|---|---|
|sh（Bourne Shell）|最も古典的な標準シェル。多くのシェルの仕様のベースになっている|
|bash（Bourne Again Shell）|shを拡張した、多くのLinuxディストリビューションで標準のシェル。補完機能や履歴機能が充実|
|zsh（Z Shell）|bashよりさらに高機能。強力な補完・テーマ機能を持ち、macOSの標準シェルにも採用されている|
|dash|軽量なshの実装。高速な起動を重視し、Debian系で `/bin/sh` として採用されることが多い|

現在使用中のシェルは `echo $SHELL` で確認でき、`chsh` コマンドでユーザのデフォルトシェルを変更できます。シェルスクリプトの先頭に書く `#!/bin/bash` のような行は「シバン（shebang）」と呼ばれ、そのスクリプトをどのインタプリタで実行するかを指定します。

## 環境変数とシェル変数

シェル上で扱う変数には、そのシェルプロセス内だけで有効な「シェル変数」と、子プロセスにも引き継がれる「環境変数」の2種類があります。

|種別|スコープ|設定方法|
|---|---|---|
|シェル変数|現在のシェルのみ|`VAR=value`|
|環境変数|現在のシェル＋そこから起動される子プロセス|`export VAR=value`|

|コマンド|役割|
|---|---|
|env / printenv|現在の環境変数の一覧を表示|
|export|シェル変数を環境変数に昇格させる|
|unset|変数を削除|

代表的な環境変数には、実行ファイルの検索パスを示す `PATH`、現在のユーザ名を示す `USER`、ホームディレクトリを示す `HOME` などがあります。

## パイプとリダイレクト

シェルの強力な特徴の一つが、複数のコマンドを組み合わせて処理を組み立てられる「パイプ」と「リダイレクト」です。いずれもプロセスの標準入出力（stdin, stdout, stderr）を制御する仕組みです。

|記号|名称|概要|
|---|---|---|
|\||パイプ|あるコマンドの標準出力を、別のコマンドの標準入力に接続する（例：`ps aux \| grep nginx`）|
|>|リダイレクト（上書き）|標準出力をファイルに書き込む（既存内容は上書き）|
|>>|リダイレクト（追記）|標準出力をファイルの末尾に追記する|
|<|リダイレクト（入力）|ファイルの内容を標準入力として渡す|
|2>|エラーリダイレクト|標準エラー出力をファイルに書き込む|
|&>, 2>&1|統合リダイレクト|標準出力と標準エラー出力の両方を同じ場所にまとめる|

これらを組み合わせることで、「あるコマンドのエラーだけをログファイルに記録し、正常出力だけを次のコマンドに渡す」といった柔軟なパイプライン処理をワンライナで実現できます。

## ジョブコントロール（バックグラウンド/フォアグラウンド）

ジョブコントロールは、1つの端末（シェル）から複数のコマンド（ジョブ）の実行状態を管理する仕組みです。

|操作|概要|
|---|---|
|command &|コマンドをバックグラウンドで実行し、シェルの制御をすぐに返す|
|Ctrl+Z|実行中のフォアグラウンドジョブを一時停止する|
|jobs|現在のシェルが管理しているジョブの一覧を表示|
|fg %1|指定したジョブ番号をフォアグラウンドに戻す|
|bg %1|停止中のジョブをバックグラウンドで再開する|
|nohup command &|端末が閉じられてもコマンドの実行を継続させる（SIGHUPを無視する）|
|disown|ジョブをシェルの管理下から切り離す|

サーバ運用では、SSHセッションが切断されてもプロセスを動かし続けたい場面が多く、`nohup` に加えて `screen` や `tmux` といった端末多重化ツールが併用されることも一般的です。
