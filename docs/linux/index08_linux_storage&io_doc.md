# Storage&IO

## ブロックデバイスとキャラクタデバイス

Linuxでは、ハードウェアデバイスも「ファイル」として `/dev` 配下に表現されます（Everything is a file の思想）。デバイスファイルは、データの入出力方式によって大きく2種類に分類されます。

|種別|特徴|例|
|---|---|---|
|ブロックデバイス|固定長のブロック単位でランダムアクセス可能。OSがバッファリング（キャッシュ）を行う|/dev/sda（ディスク全体）, /dev/sda1（パーティション）, /dev/nvme0n1|
|キャラクタデバイス|バイトストリームとして順次アクセスする。バッファリングは行われないことが多い|/dev/tty（端末）, /dev/null, /dev/random|

`ls -l /dev` の先頭文字が `b` であればブロックデバイス、`c` であればキャラクタデバイスです。ブロックデバイスはその特性上、ファイルシステムを作成してマウントする対象になります。

## LVM（論理ボリュームマネージャ）

LVM（Logical Volume Manager）は、物理的なディスク構成を意識せずに、柔軟にストレージ容量を管理できる抽象化レイヤです。パーティションを直接使う場合と異なり、後からの容量変更や複数ディスクの統合が容易になります。

|階層|概要|
|---|---|
|PV（Physical Volume）|LVMの管理下に置く物理ディスクやパーティション|
|VG（Volume Group）|複数のPVをまとめた「容量のプール」|
|LV（Logical Volume）|VGから切り出した、実際にファイルシステムを作成して使う論理的な区画|

|コマンド|役割|
|---|---|
|pvcreate / vgcreate / lvcreate|各階層の作成|
|lvextend|LVの容量を拡張（オンラインで拡張可能な場合が多い）|
|lvs / vgs / pvs|各階層の状態確認|

LVMを使うことで、「ディスクを追加してVGに組み込み、既存のLVを無停止で拡張する」といった運用が可能になります。

## RAID

RAID（Redundant Array of Independent Disks）は、複数の物理ディスクを組み合わせて、冗長性の向上や性能向上を図る技術です。ソフトウェアRAID（Linuxの`mdadm`など）とハードウェアRAID（専用コントローラ）があります。

|レベル|概要|耐障害性|
|---|---|---|
|RAID 0|複数ディスクにデータを分散して書き込む（ストライピング）。速度向上のみで冗長性なし|なし|
|RAID 1|同一データを複数ディスクに複製する（ミラーリング）|1台の故障まで耐える|
|RAID 5|データとパリティ（誤り訂正情報）を分散配置。ディスク1台分の容量がパリティに使われる|1台の故障まで耐える|
|RAID 10|RAID 1とRAID 0を組み合わせたもの。速度と冗長性を両立|構成による|

RAIDはハードウェア故障によるデータ損失への耐性を高めますが、バックアップの代替にはなりません（誤操作やソフトウェア障害によるデータ破損には無力なため）。

## I/Oスケジューラ

I/Oスケジューラは、カーネルがディスクへの読み書き要求（I/Oリクエスト）をどのような順序・タイミングで実際のデバイスに発行するかを制御する仕組みです。特に回転式のHDDでは、物理的なヘッドの移動距離を最小化するようリクエストを並び替えることで、性能に大きな差が生まれます。

|スケジューラ|特徴|
|---|---|
|noop（none）|並び替えを行わずFIFOでそのまま発行。SSDやNVMeなど、シークコストがほぼ無いデバイス向け|
|deadline|各リクエストに期限を設け、飢餓状態（特定のリクエストがいつまでも処理されない）を防ぎつつ順序を最適化|
|cfq（Completely Fair Queuing）|プロセスごとに公平にI/O帯域を割り当てる（主に旧世代のHDD向け、現在は非推奨気味）|
|bfq（Budget Fair Queuing）|cfqの後継。レイテンシの公平性を重視|

現在使用中のスケジューラは `cat /sys/block/<デバイス名>/queue/scheduler` で確認・変更でき、SSD/NVMeが主流となった現在は `none` や `mq-deadline` が推奨されることが多くなっています。
